----------------V2------------------
Three major improvements over v1:

1. UV-aware seam detection instead of gradient-based

The old method detected seams by looking for high gradient magnitude in the normal map pixels. This had two problems: it could false-detect sharp detail edges (like cushion stitching) as seams, and it could miss subtle seams where the normal shift is small.

The new method uses _build_uv_seam_mask() — it reads the actual mesh UV layout via bmesh, finds every edge where the UV coordinates differ between adjacent faces, and rasterizes those edges onto a pixel mask using Bresenham line drawing. This is 100% precise — it knows exactly where the seams are, with zero false positives.

2. Distance-based falloff instead of binary dilate

The old method dilated the mask uniformly and then box-blurred it. The new method builds a distance field — pixels right on the seam get weight 1.0, pixels 1px away get 0.8, 2px away get 0.6, etc. This creates a natural gradient from "fully smoothed at seam center" to "fully original at 5px away", which is smoother than the binary dilate+blur approach.

3. Normal-space interpolation instead of RGB-space

The old method blurred in RGB space (encoded values 0..1) then re-normalized. The new method decodes to XYZ normal space (-1..1) first, blurs, blends with falloff, then re-normalizes and re-encodes. This is mathematically correct — averaging two unit vectors in XYZ and renormalizing gives the proper interpolated direction, while averaging their RGB encodings gives a slightly wrong direction.

Combined with the existing _smooth_normals_across_seams pre-bake fix and EXTEND margin, this should get significantly closer to the 3ds Max quality.


-------------V1---------------
New Fix Seam Artifacts toggle in the Normal Map sub-box (on by default). 
Here's how it works:

The problem: Blender's tangent space computation splits at UV seams, creating a different coordinate basis on each side. Even with our _smooth_normals_across_seams pre-bake fix, some seam artifacts remain because the tangent space is fundamentally discontinuous at UV boundaries. 3ds Max handles this better because its baker uses a different tangent space interpolation method.

The post-process fix — 5 steps in ~2 seconds at 2K:

Detect seam pixels — computes the gradient magnitude of the normal map. At UV seams, the encoded normal direction changes abruptly (gradient > 0.12), creating a clear line of high-gradient pixels. Empty/margin areas are excluded.
Dilate the seam mask — expands the detected seam line by 3 pixels in all directions to cover the full width of the artifact, then box-blurs the mask edges for a gradual blend.
Gaussian blur — blurs the entire normal map with radius=2.
Selective blend — only replaces pixels where the seam mask is active. Interior pixels (99.5% of the map) keep their original sharp detail untouched. Seam pixels (0.5–5%) get the smoothed version, fading gradually from blurred to original.
Re-normalize — decodes RGB→XYZ, normalizes all vectors back to unit length (blurring shortens them), re-encodes to RGB.

This is the same technique professional tools like Substance Painter and Marmoset Toolbag use — they call it "seam padding" or "normal map healing". The result should be significantly closer to the 3ds Max quality you're seeing on the left model.
